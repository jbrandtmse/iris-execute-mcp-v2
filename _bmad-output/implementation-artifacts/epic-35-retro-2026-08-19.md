## 3. Challenges and patterns

### 3.1 The lead's own tooling caused the epic's only self-inflicted incident

The 35.9 review's HIGH finding — seven bogus ledger tally edits ("41 items"→"42 itemss", six one-row tables flipped) — traced to **the lead's commit-prep PowerShell surgery**: a `-replace '1 item','2 items'` loop intended for the 35.9 section ran file-wide. A second, smaller instance: a truncated Edit anchor corrupted a ledger header line (caught and repaired immediately). Both were caught (review caught the first; the lead caught the second) — but the pattern is real: **an edit intended for one region must be region-scoped, and the diff must be verified to touch only that region.** Rule #55 covers heredoc generation; this is the adjacent anchor/scope failure mode, and it fired on the lead's OWN artifacts where no dev/QA reviewer is looking until the code review.

### 3.2 Fixture diversity keeps paying (Rule #58 validated again)

The 35.9 BOM defect — a BOM-bearing `.cls` uploaded "successfully" while the server stored nothing (`ERROR #16021` in a string-typed `result.status`) — was invisible to every fixture set until the lead smoke hand-wrote a BOM fixture. Rule #58 named BOM explicitly; the chain still needed the smoke to catch it. And the fix's first iteration (parse-side-only strip) would have shipped the BOM to the server — proven by the rework's own mutation evidence.

### 3.3 tsbuildinfo/incremental builds can mask dist-level state (3 independent hits)

QA-35.9 (dist mutation masked until `tsbuildinfo` deleted), CR-35.9 (same), QA-35.8 (turbo cache + mtime staleness tripped the prepublish freshness leg — fail-CLOSED, the safe side). Convention adopted mid-epic: **forced clean rebuild (delete tsbuildinfo) before any dist-level mutation verification** — restore-by-rebuild alone is not proof of restore.

### 3.4 Model-attribution record split (4 recurrences, convention fixed mid-epic)

Cycle-log rows recorded the spawn tier (`model=claude-sonnet-5`); story files record agent self-reports (`claude-fable-5`). Reviews flagged it at 35.7/35.9/35.9-r2/35.8. Mid-epic fix: the lead's cycle-log rows now use `spawn_tier=`; story files keep the self-report with a reconciliation note. The harness's tier→model mapping is not observable from inside a session — the retro records the convention rather than resolving the mapping.

### 3.5 Rule #56 held after being enforced (no recurrence)

35.2/35.3/35.4 each missed a doc surface their own Dev Notes enumerated (the seventh README). From 35.5 onward every story's Dev Notes mandated the explicit `iris-mcp-all` README check with a recorded verdict — **zero recurrences** in 35.5–35.9. The enforcement worked; the rule stays as-is (no strengthening needed).

### 3.6 Full parallel `turbo run` remained flaky (35-1-DEV-1, environmental)

Per-package standalone verification was the working pattern all epic; 35.8 got a clean 29/29 turbo run once (no flake that run). Root cause still unknown; the substitution is recorded everywhere it was used. ## 5. Rules codified

`project-rules.md` is at **59**; next new rule **#60**. Candidates from this epic:

- **#60 (recommended) — Region-scoped edits, verified.** A scripted or anchored edit intended for one region of a file must be scoped to that region, and `git diff` must show ONLY the intended hunk(s) before commit. A file-wide replace of a pattern that exists in other regions rewrites them silently; a truncated anchor glues remainder text. (§3.1 — fired twice on the lead's own ledger edits; caught by review/luck, not by the edit path.) Extends #55's verify-after-generate discipline to ALL scripted/anchored edits.
- **#61 (recommended) — Dist-level verification requires a forced clean rebuild.** Incremental build caches (`tsconfig.tsbuildinfo`, turbo cache, mtime-only restores) can mask a dist mutation or an un-restored revert. Before asserting anything about what the dist contains, delete `tsbuildinfo` (and/or `turbo build --force`). (§3.3 — three independent hits this epic.)
- **Considered, not codified:** the BOM-silent-drop lesson (already covered by #58's fixture-diversity rule — the gap was application, not absence); model-attribution (a convention fix, not a rule — §3.4); "run every README example" (already covered by #36/#54 — the 35.5 smoke catch was application).

## 8. Key takeaways

1. **The epic that fixes verification findings must verify its own fixes harder than the findings were verified.** Every "simple" defect hid a wrong mechanism (arity, not lookup; content-name storage, not wrong-name storage; string-typed status, not envelope errors). The pre-story lead probe is now structurally part of story creation, and it paid for itself in three stories.
2. **The last 10% of a fix is where the epic's real defects lived** — fold negation, BOM bytes, refusal-message remedy shape. All caught because QA and review re-mutate rather than re-read, and because the lead smoke drives the tool layer with hand-written hostile fixtures.
3. **The gate is the deliverable.** Nine findings could have closed as nine one-off fixes; instead the epic closes with a permanent, armed, mutation-proven gate that would catch every one of them regressing — plus a repeatable drift check for the planning artifacts themselves.
