## 2. What went well

- **The F1+F2+F3 composition shipped as designed.** Server Manager owns connections, the governance file owns policy, the manager owns wiring — zero secrets in any client config. The 33.3 UI drives the CLI's exact code path (subprocess, `--json`), so CLI and UI can never diverge in behavior.
- **Live probing beat the spec twice.** Codex's `enabled` flag (docs-verified before wiring) and the Kimi `.mcp.json` falsification (the spec's "verified" claim was wrong; Rule #14/#42 amendment) — a config the client never reads would have shipped as a feature.
- **The safety protocol proved itself under fire.** The lead-smoke real-config overwrite was restored byte-exact from the engine's own backups — the exact disaster case it was designed for, exercised for real.
- **The late-findings net held.** Lead triage + gate-created 33.5 with terminal dispositions (2 HIGHs, 4 MEDIUMs, 12-item LOW batch fixed; 12 ledgered; ~40% of late findings proven stale and documented as such) — the 32.4 precedent executed cleanly.
- **Mutation verification is now routine.** Every 33.5 HIGH/MEDIUM fix carries a revert→red→restore record; two initially-weak pins were caught *by surviving mutants* and strengthened.

## 3. Challenges and patterns

### 3.1 Review-layer latency is systemic — 6/6 silent, then post-commit delivery

Every Epic-33 review closed on silent layers; the layers later returned with real findings (33.0: 29 findings across 3 layers; 33.4: 31). Lead triage found ~40% stale (reviewing a mutated tree — the 32.1 stale-tree mode) and 2 live HIGHs + 4 live MEDIUMs. The Epic-32 retro's RECORD-AND-OBSERVE disposition set a recurrence trigger; it fired on every story.

**Disposition (Project Lead decision 2026-07-28): ADOPT ALL THREE REMEDIES — codified as Rule #57.** Bounded-close (review may not close while layers outstanding; hard documented timeout recorded as degraded), frozen-diff (layers review a snapshot, late returns can't be stale), delivery receipts (no findings file = layer failed, never "found nothing").

### 3.2 Canonical-only fixtures blinded every tier — the epic's worst defect

jsonc-parser's `modify()` reformatting foreign entries on insert passed dev, QA, AND review because all ~40 fixtures were canonically formatted; the lead smoke's hand-written compact fixture caught it. The same blindness class recurred in 33.5 (interior comments, multiline TOML strings, comment-only documents).

**Disposition: codified as Rule #58** — byte-preservation/behavior guarantees require non-canonical fixture variants (compact, 4-space, CRLF, comment-bearing, BOM) by construction.

### 3.3 Lead error classes recurred despite prior dispositions

- **Spec error** (mine): the 33.3 Dev Notes claimed `detect --json` carries dispositions (true only of text render) — dev halted correctly; sanctioned additive fix. Rule #47 applies to the lead's "verified" claims too.
- **Smoke-script signature guesses ×3 in one story**, one overwriting the real `~/.claude.json` (mis-built spawn env — `buildClientsCliEnv(settings, extraEnv, ambient)` called positionally wrong; HOME ignored on win32 without USERPROFILE; MSYS paths into native spawns). Retro-32 §3.3 left probe-first smokes as an uncodified habit; it recurred.
- **Tally drifts** (33.4 dev's "17/350" off by 1 file/21 tests; cycle-log 21 vs 22) — Rule #51 applied at close, again.

**Disposition (Project Lead): codify ONLY fixture diversity (#58).** Smoke-script discipline stays a lead habit — but the 33.5-era smokes ran clean (iterations 1) after the incident. Re-evaluate if it recurs in Epic 34.

### 3.4 Certification honesty worked but the harness needed a hardening pass

4 clients certified-live with quoted evidence; 9 honestly dispositioned fixture-only; the Kimi CLI/TUI half verified via the print-mode agent surface with its limits disclosed. certify.mjs itself needed 33.5 fixes (keep-passing guard, record merge, fail-fast-before-write, recovery hints) — the harness's failure paths were its untested paths.

## 8. Key takeaways

1. **A layer that returns late is not a layer that worked.** The findings were real — 2 HIGHs would have shipped without lead triage + 33.5 — but "the net catches it eventually" is a cost center, not a control. Rule #57 makes the timing the control.
2. **Fixtures encode the implementer's assumptions; adversarial fixtures must encode the user's.** Canonical-only fixtures are a self-fulfilling oracle — Rule #58 makes diversity a construction requirement, not a review afterthought.
3. **Live falsification is cheaper than live apology.** The Kimi `.mcp.json` claim died in a 10-minute probe; it would have shipped as a documented feature that silently did nothing.
4. **The safety protocol earned its keep the one time it was needed.** Backups restored a real config byte-exactly after a lead error — the protocol's first real-world restore was a success.
5. **Lead discipline is the residual risk class.** Three of this epic's four process incidents (spec error, spawn-env incident, tally drifts) trace to the lead, not the agents — the tiers are strong where they're adversarial and weakest exactly where the lead works unreviewed.
