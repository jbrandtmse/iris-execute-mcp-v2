# Story 35.9: MEDIUM - `iris_doc_load` Silent Package-Prefix Loss on Glob Path Mapping

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As an **agent or developer bulk-uploading ObjectScript sources with `iris_doc_load`**,
I want **a glob shape that would silently strip the package prefix to be REFUSED at upload time with a clear, actionable error — and a way to state the package root deterministically**,
so that **I never learn about a path-mapping mistake three steps downstream as a cryptic `Class 'User.X' does not exist` compile error**.

## Context — why this story exists

Correct-course addition (2026-08-17), independent of the Epic 34 sweep: an external user's Cline transcript (`docs/bugs-2026-08-17.md`) showed `iris_doc_load` with `.../src/ClineTest/*.cls` silently uploading `ClineTest.Wumpus.cls` as unqualified `Wumpus.cls` — upload reported success; the failure surfaced only at compile as `Class 'User.Wumpus' does not exist`. This is the second independent repro of the trap Rule #17 documents as a workaround; this story is the code fix. Full evidence: `docs/bugs-2026-08-17.md` + `sprint-change-proposal-2026-08-17-doc-load-package-prefix.md` (its PRD Reliability bullet and architecture.md K1 section are ALREADY applied — do not re-apply; the general pattern-promotion decision is deferred to the Epic 35 retro per the epic's out-of-scope note).

**This story is pure TypeScript** (`packages/iris-dev-mcp/src/tools/load.ts`) — no ObjectScript handler changes, so NO bootstrap regen; `BOOTSTRAP_VERSION` must NOT move (currently `e1168c1ebe56`). Prove that.

## Lead pre-story probe — AC 35.9.2 answered live (2026-08-19, this instance, Atelier v8)

Run via `iris_doc_put` (which wraps the same `PUT /doc` endpoint the bulk loader uses); fixtures deleted after. Re-run cheaply if you extend anything (Rule #16).

**Probe 1 — PUT mismatch (same package, different class name).** URL name `LeadSmoke359.UrlName.cls`, content declares `Class LeadSmoke359.ContentName`:
- **The server stores under the CONTENT-DECLARED name** — `iris_doc_list` afterwards shows `LeadSmoke359.ContentName.cls`; nothing named `UrlName` exists.
- The PUT response carries the mismatch as a **string-typed `status` field**: `"status":"ERROR #16023: Unable to get text of LeadSmoke359.UrlName.cls\r\nERROR #16000: ... Class 'LeadSmoke359.UrlName' does not exist."`

**Probe 2 — the exact repro shape (unqualified URL name).** URL name `Wumpus359.cls`, content declares `Class ClineTest359.Wumpus359`:
- Stored under the content name again (`ClineTest359.Wumpus359.cls` in the doc list).
- The error text proves the **User-package fallback is real**: `Unable to get text of User.Wumpus359.cls` / `Class 'User.Wumpus359' does not exist` — an unqualified name resolves to the `User` package, live-verified.

**Probe 3 — why the bulk loader reported `uploaded: 2, failed: 0` in the transcript.** The PUT's mismatch signal arrives as a **string-typed `status` field**, NOT the `{status:{errors:[...]}}` envelope — the shared HTTP client throws only on `envelope.status.errors` (`http-client.ts:411-422`), so a string `status` never throws and the loader counts the upload as success. (This also means a mismatch error signal is invisible to the loader on this instance — the transcript's silent success reproduced mechanistically.)

**Consequence for the fix design (AC 35.9.3):** because the server stores under the content name, REFUSAL (not silent rename-to-content) is the correct fix — an uploaded-under-the-content-name result would "succeed" under a name the caller never said, and the tool's own `uploaded`/`documents` arrays would still carry the wrong (path-derived) names into the compile call. Cross-validate BEFORE the PUT; on divergence, refuse with both names.

### The mismatch message must be actionable

Model it on the story's intent: name the path-derived name, the content-declared name, and the two remedies (glob with the wildcard BEFORE the package directory, e.g. `src/**/*.cls`; or pass `baseDir`). Example shape:

```

```

### Traps

- **Do not "fix" by trusting the content name silently.** The server already stores under the content name; the defect is that the tool never TOLD the caller. Refusal with both names is the fix (K1 in architecture.md).
- **`extractBaseDir` behavior is unchanged** — the fix is validation, not a heuristic change. Changing the inference would be a much bigger back-compat surface (Rule #19).
- **The compile step consumes `uploaded[]`** — refused files must never reach it, or the User-fallback compile error returns.
- **Headerless/fragment files (`.inc`, some `.mac`)** have no declaration — skip cross-validation, keep path-derived. Document.
- **Rule #55:** never generate file content through a shell heredoc.
- **Windows paths:** fixtures and tests run on win32 — the glob/baseDir handling must tolerate `\\` separators (the existing code normalizes; keep that).
