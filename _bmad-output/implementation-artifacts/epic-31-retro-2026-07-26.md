## 2. What Went Well

1. **The Opus 3-layer adversarial review is where this epic's quality came from — 13 HIGHs, several of them genuinely subtle.** The standouts: one stale entry in a settings file *the suite does not own* crashed all five servers and took the working `default` profile with it; `iris-mcp-credentials set` exited **0 having stored nothing** when stdin was piped, because the prompt registered only a `"data"` listener and a pending promise doesn't hold the event loop open; `test --connect` printed a password in cleartext because V8 embeds a source excerpt in a JSON `SyntaxError`. None of these fail loudly in a green suite.
2. **Every lead smoke was a real-runtime exercise, and each one proved something the unit tests structurally could not.** 31.1 drove the *real* Windows Credential Manager; 31.2 drove the *built bin* over a real pipe (the exact HIGH-1 regression path); 31.3 drove the *built* `iris-dev-mcp` over real MCP stdio against live IRIS. All 71/71 passed with zero defects caught — which is the right outcome given review had already absorbed 13.
3. **The Rule #21 capstone had a genuine control run.** Run A (switch on, keychain-only password ⇒ live `iris_server_info` succeeds) proves the code runs. **Run B (switch unset ⇒ profile absent, call refused) is what proves the switch.** The lead re-ran the capstone independently of the dev's recorded runs rather than accepting the record.
4. **Rule #19 held under real pressure and was re-proven, not asserted.** AC 31.3.1 forced `source` onto env profiles, breaking AC 31.0.4's literal byte-identity. Rather than weaken the test, the planning artifact was amended in place (Rule 5/#42) and the gate re-verified with **three independent mutations** (extra field ⇒ 7 red; host/port/password/namespace drift ⇒ 4 red; unset default `off`→`auto` ⇒ 8 red). QA had independently mutation-checked it first.
5. **The retro-review gate closed a stale item nobody expected.** The "rebuild + reload the MCP servers" action had been carried across the Epic 29, 30 and 31 gates. Actually checking it — `iris_server_profiles` returning `toolVisibility{full,29,0}` and listing `iris_sql_analyze:advise` — showed it was **already done**. Three retros of carry-forward closed by one live probe.
6. **Deferred items were resolved by the stories that owned them, not re-deferred.** `31-0-1`/`31-0-2` were assigned to 31.1 and closed there; `31-0-3`/`31-0-4`/`31-1-1` to 31.3 and closed there. The ledger's "suggested resolution" field did real routing work.

## 3. What Could've Gone Better

1. **All 13 HIGHs came from the review layer. Zero from dev. Zero from QA.** Nothing shipped broken, so the *outcome* was right — but quality is concentrated in one stage. If review were ever weakened, skipped, or run on a lighter model, this epic's defect profile suggests what would ship.
2. **Three of the 13 were SEAM defects — a guard shipped in story N defeated by story N+1.** The clearest: 31-0-2's `username` guard was "resolved" in 31.1 by tagging such entries `unresolved` — which is *precisely* what hands them to the credential chain, which resolves by name and wrote a keychain password straight onto the inherited local username against a remote host, with zero warnings (the warn was gated on an inline password). Same species: 31.0's per-entry validation escaping to `McpServerBase.start()`, and chain link 1 becoming unreachable once 31.3's registry-shadow filter landed. **Each fix was correct in isolation; the composition was wrong.**
3. **A whole class of test fiction: doubles that model an impossible API shape.** 31.4's cancellation tests faked `getSession` cancel as `resolve(undefined)`. The installed `@types/vscode@1.125.0` overload returns `Thenable<AuthenticationSession>` with **no `| undefined`** — it *rejects*. So the cancellation handler was unreachable code, a real cancel threw an uncaught rejection at VS Code, and the suite was green on a path that cannot occur. Coverage tooling would have called it covered.
4. **Two ACs inside one epic contradicted each other and survived to the capstone story.** AC 31.3.1 (`source` on env profiles) vs AC 31.0.4 ("deep-equals its pre-feature output"). Caught only when the lead read them side by side at the ADR gate. The dev amended AC 31.0.3 and 31.1.1 but not 31.0.4, while materially changing what 31.0.4's gate proved.
5. **The deferred ledger grew by 34 items in one epic** — nearly 7× Epic 30's 5. Not alarming per item (all LOW/MEDIUM, first deferral) but the *rate* is new, and it lands on top of an Epic-30-own batch already at re-deferral count 2.
6. **The lead's own cycle-log telemetry had a gap:** `cr_complete` was written for Story 31.0 only; 31.1–31.4 were missing that stage despite every review completing. The cycle log is the durable resume state, so a resume would have believed review never ran. Backfilled from each review's actual return, marked `BACKFILLED_BY_LEAD`.

## 5. Rules to Codify

**Decision (Project Lead, 2026-07-26): CODIFY NONE. `project-rules.md` stays at 53; next new rule remains #54.**

Three candidates were considered and consciously declined:
- **Seam re-verification** (§3.2). Declined because the mechanism that caught all three seam defects — the adversarial review reading the prior story's guard — is already mandatory. Rule #52 already forces the seam to be *documented*. A rule saying "be careful at seams" without a mechanical trigger is a wish, not a rule.
- **Test-double fidelity** (§3.3). Declined because **Rules #14/#16 already require verifying third-party API shapes from source**; they simply weren't applied to a test double. Adding #54 would let us point at a rule and feel covered instead of applying the one we have.
- **Cross-AC contradiction check** (§3.4). Declined as a single incident, adequately handled by the existing Rule 5/#42 amend-in-place discipline once spotted.

**Rules EXERCISED and held** (not re-codified, per #1):
- **#14/#16** — live probes beat assumptions repeatedly: the dev live-probed `findCredentials(service)` and found enumeration IS supported (contrary to the story's caution); the review read `@types/vscode` directly and found `getSession` rejects rather than resolving; a web-fetch of the same file silently truncated and reported the MCP types missing.
- **#19** — additive gate held under genuine pressure and was re-proven by mutation, not asserted (§2.4).
- **#21/#49** — the capstone was a live round-trip with a real control run.
- **#22/#26** — every per-story lead smoke drove the BUILT artifact in a fresh process.
- **#25** — `gen:governance-baseline:check` only; the frozen file stayed byte-unchanged all epic.
- **#31** — no tool or prompt count moved; adding a FIELD to `iris_server_profiles` is not a count change; the extension stays out of `pnpm-workspace.yaml` so turbo's task count never moved.
- **#36** — the 31.4 env-contract test was upgraded at review to *execute* `packages/shared/dist/{config,profiles}.js` as the oracle rather than restate the contract in comments; mutation-verified additive.
