## 2. What went well

1. **The beta loop actually closed.** A defect reported from real use on 2026-09-10 was analyzed, planned, fixed, and verified on the reporter's own instance (`ocupilot-iris`, 16/16 then 9/9 smoke legs) within the same cycle — while that instance was running the reporter's own suites concurrently.
2. **Probe-first overturned written claims four times, before code was built on them.** The Atelier drain is DELTA (so a "full envelope from the drain" is impossible after a partial drain); a cancelled run stays `$D=10` forever (so the result table cannot mean "running"); `Open tNull:::1` never sets `$Test` (the `1` is not a timeout); `$Name` canonicalizes numeric-looking string subscripts. Two of these were in ACs the lead had written and were amended in place (Rule #42) before dev.
3. **Rule #37 did its job.** The trigger fired at the 36.0 gate on 48 items; 3 were folded into the story that already rewrote their code and 45 reached terminal disposition with evidence (27 resolved / 10 closed-with-evidence / 8 closed-by-decision, 0 re-deferred).
4. **The security fix is provable, not asserted.** 20,000 hostile inputs checked against IRIS's own reference parser plus native node reads; the live gate goes RED 17/20 against the pre-fix class on the real HTTP route, including the read-only-preset bypass itself.
5. **`sequential_sync` layers fixed the review-bound problem immediately.** After the single DEGRADED close, every subsequent review ran its three layers one at a time, each with its own armed timer, and all 15 layer runs delivered inside the bound (longest 699 s of 1200 s).
6. **Deliberate breakage kept finding what green suites hid.** A planted type error exposed that a build change had removed every test file from type-checking; a reverted deployed class proved each live gate could fail; a seeded stale flag proved a capture-slot fix.

## 3. Challenges and patterns

### 3.1 A suggested resolution is a lead, not a fact (fired 4×, once as an outage)

Story 36.3's dev implemented the ledger's literal suggested fix (`$Test` after `Open`) on a bootstrapped handler and deployed it: **100% of requests failed** until it was caught and reverted in the same session. The recorded root cause was itself wrong, and only the code review's live probe established that `Open tNull:::1` never sets `$Test` at all. The same class recurred with `34-4-R7` (the claimed fix mechanism was not the real one), `34-5-R5` (a correction whose derivation was wrong while its value was right), and the `36-2-CR-1` row's own suggested one-liner (it would have double-escaped a legitimate input — the dev's probe caught it first).

**Convention carried forward (not codified):** probe a suggested fix before implementing it; never deploy an unverified change to a bootstrapped handler without immediately running the armed gates; keep the pre-change class content to restore from.

### 3.2 A config change can switch a gate off silently

The `33-5-L2` fix added `**/__tests__/**` to `tsconfig.base.json`'s `exclude` to keep compiled tests out of published tarballs. It also removed every test file from `type-check` and `build` across all 7 publishable packages — vitest transpiles without type-checking, so every suite stayed green. QA proved it with a planted type error. The lead ruled it a regression introduced by the story and therefore fix-in-story; review reverted the tsconfig change and kept tests out of tarballs with a `files` negation instead (188 test files had been shipping in the dev package alone), reverting the fixture relocation, five `@types/node` additions and the lockfile change that had only served the tsconfig approach.

**Convention carried forward (not codified):** after changing build/test configuration, prove each gate can still fail.

### 3.3 Planning misses that the gate's mechanical work caught

The correct-course plan that opened this epic **omitted the Rule #37 obligation entirely** — 48 items at their third deferral, recorded as a forward obligation by the Epic 35 gate. The 36.0 gate's commissioned mechanical inventory surfaced it, and the epic grew a burn-down story (36.3) and then a security story (36.4) after the fact. The same gate's AC named a batch that no longer existed (`34-6-CR-10/-11` were already resolved). Both were amended in place with markers rather than silently corrected.

### 3.4 Review depth kept paying, including on the lead's own work

Reviews found 8 HIGHs the dev and QA stages missed, and iteration 2 of the 36.0 review found a contradiction that iteration 1's own patch had introduced into the 36.1 contract. The 36.2 review found a pre-existing security HIGH by reading the handler its story merely touched. The 36.3 review corrected the recorded cause of the outage. Lead-authored planning artifacts were in review scope throughout and were corrected several times.

### 3.5 Environmental noise remains, and is ledgered rather than normalized

`36-0-QA-3` (OS `MessageResendTest`, external sample package absent), `36-1-QA-3` (client-config macOS `/private/tmp` realpath), `36-1-QA-4` (client-config parallel flake), `36-4-CR-4` (two live gates flake when run in parallel). Each is a ledger row with a reproduction, not a "known failure" in prose.

## 7. Decisions made at this retro

- **`36-4-CR-1` (HIGH, silent bootstrap downgrade): DEFERRED by Project Lead decision, to become a dedicated story in a future epic.** Rationale on the record: it is pre-existing (36.4 raised the stakes rather than creating it), its fix changes a contract shared by all five servers (`Setup.GetBootstrapVersion`, the generator, probe semantics), and no change can stop already-built older servers from downgrading. ## 8. Key takeaways

1. **The written record of a defect is a hypothesis.** Every story in this epic found at least one recorded claim that was wrong when probed — including claims in ACs the lead wrote from the previous story's own notes. The cheapest moment to discover that is before code is built on it.
2. **A gate that stops running is worse than a gate that fails.** Two of this epic's most valuable findings were about coverage silently disappearing (type-checking dropped by a config change; live gates missing from the prepublish list), and both were found by deliberately breaking something rather than by reading output.
3. **Rule #37 converts drift into a decision.** An obligation recorded one epic earlier forced 45 items to terminal disposition here — and the same machinery is why the one HIGH left open is a tracked, owned decision rather than a silent carry.
