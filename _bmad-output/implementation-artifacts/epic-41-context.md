# Epic 41 Context: Companion Skills & Rules Pack

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Agents that write ObjectScript get the project's hard-won rules in three forms: one short, always-on pre-write checklist; 6–10 knowledge skills that the model loads when it needs them; and the workflow skills generated from the suite's MCP prompts. All three ship as one generated pack, `packages/client-config/skills-pack/`, and the `iris-mcp-clients skills install|uninstall` CLI of `@iris-mcp/client-config` puts it into each MCP client's native location. The competitor's MIT notice ships wherever adapted content ships. The pack is our own equivalent of the competitor's kit (intersystems-community/iris-agentic-dev), not a copy. Agents choose skills by their description, and MCP prompts are slash commands only a user can invoke, so shipping the content as skills is what lets agents actually find it. This is the only epic on `feature/feature-wave-7-skills-pack`. Story 42.8's Claude Code plugin consumes the same pack later.

## Technical Decisions

- **AD-28, prompts and workflow skills.** MCP prompts are authored once, in `packages/*/src/prompts/`; the workflow skills are generated from them (`gen:skills`, which writes only `skills/`). `scripts/lib/prompt-catalog.mjs` `loadAllPrompts` imports each server's `dist/prompts/index.js`, so `gen:skills` and `validate:prompts` need built dists. An omitted `arguments` gets -32602 on the all-optional prompts (DW-617, owned by 43.1).
- **AD-28, skill frontmatter.** Frontmatter on line 1, no BOM: `name`, `description`, optional `metadata` whose one key is `iris-tools-preset` (`core`/`developer`/`full`). `name` equals its directory, matches `^[a-z0-9]+(-[a-z0-9]+)*$`, ≤ 64 characters, without `claude` or `anthropic`; `description` ≤ 1,024 characters, no XML-like tag. `check:provenance`'s `skill-frontmatter` rule enforces it through `readSkillFrontmatter(text, dirName)` (`scripts/lib/skills-pack.mjs:350`, returns `{fields, metadata, problems}`); `skillFrontmatterProblems` (`:499`) is a view of it.
- **Conventions, "Pack names".** Hand-authored pack content carries the suite prefix (`iris-mcp-<name>`, `IRIS-MCP-THIRD-PARTY-NOTICES.md`). Generated workflow skills keep their prompt names (AD-15), so a same-named foreign skill directory is possible on install (a conflict).
- **Conventions, "Marked blocks".** A suite-owned block sits between `<!-- IRIS-MCP-RULE:<name>:BEGIN -->` and `<!-- IRIS-MCP-RULE:<name>:END -->`, matched as exact whole lines, owned and replaced whole; everything outside is preserved byte for byte. A UTF-8 BOM at byte 0 is not part of line 1 and stays at byte 0. Own markers that are not exactly one BEGIN line followed by one END line are reported with their line numbers and nothing is written. A last line without a line ending gets one in the file's own style before a block is appended, and uninstall removes it. The hosts are `AGENTS.md` and `GEMINI.md`.
- **AD-28, one pack.** The committed, generated, DO-NOT-EDIT `packages/client-config/skills-pack/`; only `pnpm gen:pack` writes it, and `gen:pack:check` fails on any MISSING, DRIFT or STRAY file. It reads the generated `skills/` and `skills-pack-src/` (`knowledge/<name>/SKILL.md`, `rules/<name>.md`, the notice, a contributor `README.md` that is not copied) and needs no build.
  - **Shape** (23 files): `skills/<name>/SKILL.md` for the 18 skills; `rules/claude-code/<name>.md` (the source bytes, no `paths:`); `rules/cursor/<name>.mdc` (`alwaysApply: true` frontmatter, then the source bytes); `rules/agents-md/<name>.md` (BEGIN, the source bytes, END); the notice and the catalog `README.md` at the root.
  - **Consumers.** Shipped through client-config's `files` (`["dist", "!dist/**/__tests__", "skills-pack"]`), with no lifecycle hook. The installer reads it at `DEFAULT_PACK_DIR` (`new URL("../skills-pack/", import.meta.url)`). The plugin (42.8) roots at it and ignores `rules/`.
  - **Installer routes.** `claude-code`: `.claude/skills/` and `.claude/rules/`; `cursor`: `.agents/skills/` and `.cursor/rules/<name>.mdc`; `gemini`: `.agents/skills/` and the block in `GEMINI.md`; `agents`: `.agents/skills/` and the block in `AGENTS.md`, for every other client, VS Code / Copilot included (an `applyTo:` instructions file attaches only to files the agent creates or modifies). ## UX & Interaction Patterns

- **Installer flow (as built).** The file-level plan is printed first, and the same preview is used for dry runs. It never shows a user file's bytes or a modified file's content. A write happens only after `--yes` or a TTY confirmation. A successful run ends `Done: <n> path(s) changed for <displayName>.`, and the notes tell the user any follow-up.
- **Claude Code with a `CLAUDE.md`.** The rule goes to `.claude/rules/`, and `N-claude-md` tells the user to add `@AGENTS.md` to `CLAUDE.md` if they want it read.
- **Catalog.** The pack README lists every knowledge skill, every workflow skill and the rule, each with what it is for and any declared preset, then Layout and Third-party content. Under DW-624 it must also say the presets are not nested.
