## Notes
- **Tally:** NOT-A-GAP 0 / PARTIAL 8 (G22, G25, G27, G30, G32, G33, G35, G37) / CONFIRMED-GAP 14 (G18-G21, G23, G24, G26, G28, G29, G31, G34, G36, G38, G39). The PARTIAL labels were derived from the table rows, not counted by hand.
- **How "generic-only" was decided:** `iris_execute_command` runs arbitrary ObjectScript, so in principle every server-side capability can be reached generically. Calling everything generic-only PARTIAL would make the verdicts meaningless. I used generic-only PARTIAL only when (a) one SQL statement through `iris_sql_execute` delivers the capability and the repo itself shows that surface is SQL-reachable (G22, G30, G33), or (b) a dedicated tool returns the raw material and the agent only has to interpret it (G25). Capabilities about safety or confirmation (G21, G29), sessions or transport (G18-G20), or multi-step orchestration (G23, G24) are not delivered by generic reachability, so they stay CONFIRMED-GAP. Reaching something only through `iris_execute_command` (G26, G28, G38) is noted but not counted.
- **Surprise 1:** A read-shaped header search (G32: by item, status and time window, returning count plus sample) already exists server-side. It is reachable only through `iris_message_resend resendFiltered` with `dryRun`, which governance classifies as a write and disables by default. Promoting it to a read action on `iris_production_messages` looks cheap.
- **Surprise 2:** `iris_message_resend preview` already reads message-body content (1 KB, streams only), which partly covers G27 and G35. It has no PHI policy.
- G19 is a gap on record: the data package has an explicit deferred placeholder (`debug.ts`, FR106/FR107) that was never implemented.
- Out of budget, not checked: whether `iris_production_status detail=1` returns per-item target connections, which would be raw material for G39. The tool description (production.ts:233-235) lists only name, class, enabled and adapter.
