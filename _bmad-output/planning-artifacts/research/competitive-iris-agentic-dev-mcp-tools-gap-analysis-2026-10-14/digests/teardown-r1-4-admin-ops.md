## Shared mechanism notes (apply to every row)
- **The "generator" (`execute_via_generator`)** is how most of these tools reach IRIS. It PUTs a throwaway class `IrisDevTmp.IrisDevRun<12-hex>` through Atelier `PUT /doc/...`. The class wraps the ObjectScript snippet in a `[SqlProc]` classmethod and captures `Write` output to a temp file. The proc is called as SQL `IrisDevTmp.IrisDevRun<id>_Execute`, and a `ScratchGuard` deletes the class afterwards. Nothing persistent is installed on the server, but each call is a class compile in the target namespace (often `%SYS`). Source: iris/connection.rs:522, :600-621, :732-757.
- **SQL path (`iris.query`)**: Atelier `POST /api/atelier/vN/<ns>/action/query` with `{query, parameters}`. Source: iris/connection.rs:925-936.
- **Write gate**: `write_gate::CLASSIFICATION` (tools/write_gate.rs:426+) maps each tool or action to ReadOnly, Write or Destructive. Write needs `IRIS_WRITE_TOOLS_ENABLED`. Destructive also needs `IRIS_DESTRUCTIVE_TOOLS_ENABLED` (write_gate.rs:154-155; admin_tools.rs:14-17 says "writes are on, the tier is off"). It is enforced centrally in `call_tool` (tools/mod.rs ~9462 `write_gate::gate_check`).
- **Third switch for iris_admin writes**: `IRIS_ADMIN_TOOLS=1|true`, checked inside each admin write handler (tools/admin.rs:22-33).
- **Multi-instance**: every tool takes an optional `server` (a registered instance name).
- **Output schemas**: every tool declares `output_schema = oneof_output_schema::<...>()`. Typed responses exist for most; `serde_json::Value` is used for sysperf and mirror_status.
- **Tiers**: iris_admin exists **only in the Merged tier**. It is pruned from Baseline (the default) and Nostub by the `merged_only` list at tools/mod.rs:2731. The other 11 tools are in all three tiers.

## Leads worth chasing
