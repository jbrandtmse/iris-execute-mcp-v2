## Notes
- Mechanical tally from the Verdict column: 0 NOT-A-GAP, 7 PARTIAL (G3, G6, G9, G10, G11, G14, G16; of these G11, G14 and G16 are generic-only or near-generic), 10 CONFIRMED-GAP (G1, G2, G4, G5, G7, G8, G12, G13, G15, G17).
- Strongest refutation found: G9 sub-claim (a), "listing the include files in a namespace", is fully covered by `iris_doc_list` (`category:"RTN"`, `type:"inc"`). The G9 claim as worded is therefore overstated. Only the per-include macro list and a parsed signature are really missing.
- G3 is weaker than claimed: a multi-document inline fetch already exists as XML (`iris_doc_xml_export` export), and a multi-document fetch to disk exists as `iris_doc_export`. Only an inline UDL batch is missing.
- G2/G1 caution: the repo DOES contain a mature line-span surgery and diff engine (packages/client-config/src/diff.ts, write.ts). It targets MCP-client config files, not IRIS documents, so it does not refute G1/G2. It is reusable prior art if those gaps are built.
- G6 residual: I could not verify inside the firewall whether Atelier `action/compile` honours wildcards server-side. If it does, passing `MyApp.*.cls` straight through `iris_doc_compile` might already work. A live probe is recommended before treating G6 as a build item (Rule #16).
- Every CONFIRMED-GAP except G7, G8 and G17 can be reached generically with raw ObjectScript or SQL through `iris_execute_classmethod`, `iris_execute_command` or `iris_sql_execute`. Those do not count as capabilities under this audit's strict rule.
