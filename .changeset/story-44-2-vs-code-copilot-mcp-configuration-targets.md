fix: `iris-mcp-clients` writes VS Code (Copilot) entries to the files the Copilot harness reads: `~/.copilot/mcp-config.json` (`$COPILOT_HOME/mcp-config.json`) and the workspace `.mcp.json` (Story 44.2, DW-721)

- The `vscode` adapter targets the user file `~/.copilot/mcp-config.json` and the workspace-root `.mcp.json`, both keyed `mcpServers` with `${VAR}` references and no `inputs` array. A user entry is `{type, command, args, env, tools}`; a project entry is exactly what `claude-code` writes into the same file. `env-reference` writes `${IRIS_PASSWORD}`, `server-manager` writes no secret, and only `explicit` writes a literal.
- A `.mcp.json` shared with Claude Code gives each entry one owner: the client that wrote it. The other client's `apply` (an identical entry included), `disable`, `enable` and `remove` of it exit 1 and write nothing; nothing is adopted. Configuring both clients for one project means picking one client per server (to switch, `remove` the entry with its owner, then `apply` it with the other). An entry that no record names for the file belongs to Claude Code. The owner's `disable` and `remove` say that the other client reads the file. `detect`, `status` and `doctor` list and check it once (`sharedWith`). Ownership and stash records now carry the config file they were written to (an additive optional `path`), and only a record of the same file counts, so a record from another project never blocks a write; a stash is enabled only in the project where it was disabled (after a project folder moves, run `apply` again). A record or stash written before this change has no file and keeps matching in every project until the client that wrote it replaces or drops it in a project (the CHANGELOG says which commands do). Only the Claude Code and VS Code project scopes share a file, whatever the working directory.
- Entries the manager wrote into VS Code's old `mcp.json` files are reported (`status` `legacy`, `doctor` `vscode-local-harness-entries`) and moved out by the next `apply`, through the write protocol, with foreign bytes intact.
- Deprecated the exports `ensureInputs`, `presentInputIds`, `VscodeInput` and `VSCODE_PASSWORD_INPUT_ID` (still exported; removed in the next major): no adapter uses native inputs any more, so `ensureInputs` refuses for every client. The `inputsMerged` field of the `apply` envelope stays, always `[]`. Adapter data is `2026-11-22.1`.

The end-of-epic release must carry `@iris-mcp/client-config` (the CLI the MCP Clients view runs). Nothing is published by this change.
