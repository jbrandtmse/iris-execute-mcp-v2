feat: the bootstrap leaves an IPM installation alone, and the `zpm` fallback text names the package version (Story 42.4)

- When the IPM-only class `ExecuteMCPv2.InstallGuard` exists in the namespace, IPM installed the `ExecuteMCPv2` classes there. At startup, on every path that would write (an older deployment, a deployment installed but not configured, no `Setup` class) the bootstrap uploads, compiles and configures nothing, and logs one `[WARN]` line that names the `zpm` commands. A guard that appears only at the re-check before a compile comes after the class documents were uploaded: those stay, and the compile and every later step are skipped. `BootstrapResult` gains an optional `ipmOwned` field, present only when `true`. With no guard class the result is unchanged, and a read of the guard class that fails for another reason than a 404 is treated as unknown: nothing is written.
- `MANUAL_INSTRUCTIONS` item 3 (logged when Configure fails) names `zpm "install iris-execute-mcp-v2 <version>"` in the target namespace, its prerequisites, and the registry command; it no longer says to run it in any namespace.
- The embed exports `IPM_MODULE_NAME` and `IPM_INSTALL_GUARD`, and `BOOTSTRAP_VERSION` moves from `0.0.2+1.995fbbb1055d` to `0.0.2+2.244fe8623c76` (the install guard joins the hashed content). `ipm/module.xml` is generated by `pnpm gen:bootstrap`.

No tool, action, governance key, annotation, description, REST route or environment variable is added or changed.
